# 参考视频自动换稿

## 交付约定

只需**参考原视频＋替换脚本文案**即可开始。把原片作为视觉模板，把用户文案作为内容依据。自行完成分析、对应时间轴、清除旧字、适配新字、动画、检查和MP4输出，不要求用户填表、标时间码、选软件或逐镜确认。质量目标是已验收的“原底片保留＋文字动效重建”，不是捏造看不见的源图层或承诺像素级一致。

支持最短请求：

> 按参考视频换成下面的文案，其他按默认设置：
> 斗志昂扬
> 健康险与你始终在一起
> 就医陪诊，一路有人陪
> 英文统一为 HEALTH CARE

只在视频/文案确实缺失、多个候选素材无法区分，或存在会改变数字与含义的歧义时，一次性询问必要信息。资料已在当前会话或可访问文件中时先定位读取，不反复索取。分行、字号、短句划分和合理重复自行决定，不把正常制作检查变成多轮向用户提问。

## 默认设置

优先级：本次明确要求 ＞ 本次提供的项目、字体、品牌规范 ＞ 下列默认。

| 项目 | 默认处理 |
|---|---|
| 交付 | H.264 MP4、yuv420p、faststart |
| 画幅 | 1080×1920竖版；竖版原片等比适配 |
| 横版原片 | 完整等比容纳原画面，用参考背景色补边，不裁掉主体、不拉伸；需要重排时保持原视觉层级 |
| 时长、帧率 | 延用原片节奏、时长和帧率；空屏不擅自加内容 |
| 声音 | 默认不含音轨；明确仅去配乐且保留人声/音效时按要求分离，不直接全静音 |
| 字体 | 优先采用用户提供的授权字体；否则自动获取 Noto Sans CJK SC Bold，PS名 `NotoSansCJKsc-Bold`。公开版不含三极字体，默认字形与个人版不同 |
| 配色和元素 | 取自本次参考片，不把所有参考统一改成红金色 |

低分辨率底片放大不等于细节恢复；让新文字按输出分辨率独立渲染。保留原素材，不覆盖原片。不要携带原使用者的文件地址、表格链接、改稿或业务数据到新任务。

## 1. 素材与能力检查

先读 `references/workflow.md`，制作动画计划时读 `references/plan-format.md`。公开版首次使用默认字体时，由 `scripts/font_setup.py` 从固定官方版本自动下载并校验，成功后缓存复用；无需用户另外提供字体。网络不可用时检查已有授权字体，并如实说明缺失资源。包内资源可用时直接运行；只复制了本文时，按这些原则在任务目录实现代码，不让用户补写技术提示词。

1. 检查原片宽高、旋转、帧数、帧率、时长和音轨，用实际解码帧确认方向和尺寸。
2. 检查FFmpeg/ffprobe、Python及Pillow、NumPy、SciPy、fontTools；缺少依赖时先寻找已有运行时，常规依赖可在任务环境安装。
3. 检查真正可运行的AE、aerender或AE连接。Skill文件存在不代表AE已经安装。
4. 有可编辑AE工程且能运行AE：优先替换原文字层并保留属性和效果。只有MP4或没有AE：进入逐帧合成，继续交付MP4，不以“请给AE工程”结束本来可完成的工作。
5. 完全没有可执行的视频处理环境时，如实说明缺失；不能把提示词、JSX或代码称为已生成视频。

`SKILL_DIR`为本Skill目录，`JOB`为任务目录，均使用实际绝对路径：

```bash
python3 "$SKILL_DIR/scripts/video_pipeline.py" prepare --video "$JOB/reference.mp4" --job "$JOB/analysis" --step 0.1
```

## 2. 自动识别时间轴并匹配新稿

短快闪片先每0.1秒抽帧，看完整画面与文字区；转场、逐字入场、旋转和巨字镜头再逐帧检查。抽样频率不是输出帧率。OCR可辅助，不能用音频转写代替画面识别，也不能仅凭几张缩略图判断整片。数字排序帧文件，避免时间顺序出错。

内部建立“原文字组→起止帧→动画特征→新文案”映射，不要求用户先操作表格。识别中文、英文、数字、叠影、两行滚动、旋转、缩放、逐字到达和转场残片。

- 有原文→新文、时间码、序号或镜头说明时优先服从。
- 只有分行或整段文案时，按语义、标点、信息层级与数字重点拆分，再按叙述顺序和原槽位结构匹配。完全换题时不要强求新旧文案同义。
- 连续相同文字快闪通常是一组；新稿只写一次时复用到重复镜头。新稿明确写“取号／就诊”时分别匹配，不能误合并。
- 段数不一致时，合理合并短句、分行或利用重复镜头。不得漏句、补数据、增加口号、改变数字/单位/百分号/加号。
- 长稿先分行、适度缩字号；仍不可读时才询问保留时长还是允许延长，不用极小字假装完成。
- 超大字残片属于转场，禁止把“无法辨识”“…拓…（转场局部）”等分析备注写进成片。能归属相邻已替换文字组时同步替换；明确保留或没有改稿时保留原转场并记录。

语言规则：用户已给中英文则逐字采用，仅调整换行；“英文统一XXX”应用到所有原英文槽位，明确取消者除外。只有中文但原片有英文时自动配简短对应英文，并记录为自动翻译，不保留过时旧英文、不杜撰品牌官方英文名。原片没有英文时不添加。`无英文／不要英文／—`表示不显示，空白字段不一定代表删除。

## 3. 保留底片并重建文字

区分背景、几何/粒子、中文、英文与转场，尽可能保留非文字源像素。禁止大块不透明色块盖字；禁止用文生视频重新生成整条来替代精确换稿。

清除需替换的主字、旧英文、叠影、模糊拖尾和进出场残留。根据当前视频制作逐帧遮罩，用邻近无字帧、对齐的时间中值或局部修复恢复背景。纯色/渐变MG可颜色分离；实景移动底需跟踪和时序修复，不能照搬红金片阈值。

先检查无字底片，再叠新字。同色圆环、菱形、光条与文字粘连时，建立装饰保护遮罩。不要对整条字幕带做强开运算，否则会抹断细线。具体处理见 `references/workflow.md`。

按实测原片节拍与轨迹重建：

- 逐字入场：按新字数重新分配同一入场时长，保留方向、错峰、弹性与拖尾。
- 叠影：主层和影层全部绑定新稿，沿用层数、间距、透明度和扩散节拍。
- 菱形快闪：保留原线框，匹配文字缩放脉冲。
- 旋转/圆环：文字、英文、装饰分别处理；不要让原本水平的英文跟主标题一起转。
- 两行滚动：保留出入场顺序与层级，保证新稿完整。
- 巨字转场：保留冲屏/缩回特征，适配新长度；稳定阅读段不意外裁字。

生成标准`plan.json`，同一份文案和关键帧驱动外部渲染与可选AE脚本。`check-plan`验证文本、缺字、轨道边界，不能替代看画面。

```bash
python3 "$SKILL_DIR/scripts/video_pipeline.py" check-plan --plan "$JOB/plan.json"
python3 "$SKILL_DIR/scripts/video_pipeline.py" render --plan "$JOB/plan.json" --output "$JOB/final.mp4"
```

AE路径建立原生文字层、中心锚点、位置、缩放、旋转、不透明度和所需模糊，使用匹配名及ES3兼容JSX；有真实AE时完成预览与渲染。仅生成脚本不能声称AE已渲染。可选导出见 `references/plan-format.md`。

## 4. 内部验收后交付

至少完整检查一次。有具体问题就修复并复查相关帧，不发明显半成品让用户挑错，也不无故重复渲染。

- 内容：逐段核对中英文、标点、数字、单位、重复层和转场层；没有漏句、错译、旧字双影。
- 画面：看全部稳定段和每个切点前后至少3帧；特别检查旋转文字远端、满屏巨字、英文两端与圆点交叠处。
- 结构：对照镜头顺序、动画类型、粒子、线框、圆环、光条、空屏和节奏。只为字体/字数变化做必要布局适配。
- 可读性：稳定文字不过界、数字完整，实际解码全片无坏帧。
- 技术：检查方向、尺寸、帧率、帧数、时长、音轨；VFR规范化时记录实际变化。

```bash
python3 "$SKILL_DIR/scripts/video_pipeline.py" verify --video "$JOB/final.mp4" --plan "$JOB/plan.json" --report "$JOB/validation.json"
```

主交付为可播放/下载的MP4，按平台要求持久保存；不能只给代码、方案或静态图。用户需要编辑或环境适合时附AE脚本/工程，没有要求时不额外做在线表格。简述字体、规格、声音；确有差异时具体说明受影响镜头。非原生AE输出准确称为“原片底片＋文字动效重建”，不能称原作者工程直接换字或逐像素完全相同。
