# MotionForge AI｜AI 自动生成 MG 动画视频

## 交付约定

只需**参考原视频＋替换脚本文案**即可开始。把参考片作为运动、节奏和风格模板，把新稿作为内容依据。自行完成镜头拆解、文案适配、素材制作、动画合成、验收和MP4输出，不要求用户填表、标时间码、选软件或逐镜确认。

支持最短请求：

> 参考这个视频，按下面的脚本制作 MG 动画：
> 灵感即刻出发
> 让每个想法动起来

也支持“只用参考片前20秒，文案按顺序能放多少放多少，画面按新稿重做”。这里的20秒是本次请求的约束，不是所有任务的默认时长。

仅在视频/文案确实缺失、多个候选素材无法区分，或歧义会改变数字与含义时，一次性询问必要信息。资料已在会话或可访问文件中时先定位读取。分行、短句划分、排版和日常制作检查自行完成，不把正常制作变成多轮追问。

## 先确定制作模式和范围

| 用户意图 | 执行方式 |
|---|---|
| 只替换文字、其他原样保留 | **精确换字**：保留非文字源像素，清除旧字并重建文字动效；不重生成整片 |
| 画面按新稿重做、把新脚本填入参考快闪模板、生成同风格MG | **镜头重建**：保留参考的镜头结构、运动方式、动效层次、转场和节拍，按新内容重做场景及承载信息的元素 |
| 仅给参考片和新稿，未指定方式 | 按参考模板制作；沿用内容仍匹配的画面，重做与新稿含义冲突的内容画面。自行记录各镜头采用保留、局部替换或重建，不要求用户选择技术模式 |

“按脚本重做画面”改变的是场景语义，不授权随意更换参考的动画语言；“完全复刻动效”也不等于继续保留与新主题无关的旧画面。仅叠加新文字不能作为已完成镜头重建的依据。

明确记录参考起点、参考终点、输出时长、文案使用策略。未指定时分析整片并延用原时长；指定“前N秒”时严格使用该片段，不用后续镜头填空。使用源帧号和输出帧号两套坐标，源片段起点映射到输出第0帧。参考不足或约束互相冲突时说明具体缺口，不默默循环、拉长或加速。

## 默认设置

优先级：本次明确要求 ＞ 本次提供的项目、字体、品牌规范 ＞ 下列默认。

| 项目 | 默认处理 |
|---|---|
| 交付 | H.264 MP4、yuv420p、faststart |
| 画幅 | 1080×1920竖版；明确要求其他尺寸时采用该尺寸 |
| 横版原片 | 完整等比容纳、不拉伸、不裁掉主体；需要重排时保留视觉层级 |
| 时长、帧率 | 延用所选参考范围的节奏、时长和帧率；空屏不擅自加内容 |
| 声音 | 默认不含音轨；明确只去配乐时按要求保留人声/音效 |
| 字体 | 优先采用用户提供的授权字体；否则自动获取 Noto Sans CJK SC Bold，PS名 `NotoSansCJKsc-Bold`。公开版不含三极字体 |
| 配色、质感 | 取自本次参考，不把不同参考统一改成同一套颜色或动画 |

保留原素材，不覆盖原片。低清底片放大不等于恢复细节，新字应按输出分辨率独立渲染。不要携带原使用者的文件地址、改稿或业务数据到新任务。

## 1. 素材与能力检查

先读 `references/workflow.md`。镜头重建或混合制作还须读 `references/motion-remake.md`、`references/shot-contract.md`；编排渲染计划时读 `references/plan-format.md`。

1. 检查参考视频宽高、旋转、帧数、帧率、时长和音轨，用实际解码帧确认方向和范围。
2. 检查FFmpeg/ffprobe、Python及Pillow、NumPy、SciPy、fontTools；先找现有运行时，常规缺失依赖可在任务环境安装。
3. 镜头重建时先读取可用的after-effects制作指南并协调其工作流，无需用户再次点名；用户指定AE时同样执行。检查真实AE、aerender或连接是否可执行，仅安装Skill不代表有AE。未安装该指南时使用本包制作规则与已具备工具继续执行。
4. 有可编辑AE工程且能运行AE时，优先在源工程修改。没有源工程时逐镜重建；没有AE时用可执行合成工具处理，不以索要AE工程结束本来可完成的工作。
5. 生成式工具可制作所需场景素材；先验证能力、授权和实际产物，再纳入计划。不得假称调用模型或生成视频，也不把特定模型或分辨率强制应用于每次任务。
6. 包内渲染器只实现其文档所列能力。遇到透视、三维遮挡、形变等未覆盖效果时，扩展实际合成、预渲染对应镜头或使用可用AE能力；不能删掉效果以迁就现有脚本。

`SKILL_DIR`为本Skill目录，`JOB`为任务目录，均使用实际绝对路径。保留原视频作为来源，再按本次范围分析：

```bash
python3 "$SKILL_DIR/scripts/video_pipeline.py" prepare --video "$JOB/reference.mp4" --job "$JOB/analysis" --step 0.1
```

用户限定“前20秒”时，在该命令追加 `--start 0 --duration 20`；其他范围替换对应秒数。`media.json`记录所选窗口和实际帧信息，渲染计划采用该窗口内从0开始的帧号。不要预先丢失原视频与片段的对应关系。

## 2. 拆解参考并匹配新稿

短快闪片先每0.1秒抽帧；所有切点、超短闪帧、逐字入场、透视变化、遮挡和复杂转场再逐帧检查。看完整画面，不只看字幕区。抽样频率不是输出帧率；OCR仅辅助画面识别，不能用音频转写或少数缩略图代替完整分析。按数字顺序读取帧文件。

为每个镜头分别记录**文字、镜头运动、场景动画、装饰元素、转场**五项；不存在的项目明确标为无，不能漏记。记录起止帧、重要动作发生帧、层级和遮挡关系，再映射新文案与新场景。镜头重建按 `references/shot-contract.md` 写入可检查的镜头清单，并与实际渲染计划关联。

- 优先服从原文→新文、时间码、序号或镜头说明。普通文本按语义和标点拆分，保持原叙述顺序；完全换题不强求新旧句子同义。
- 连续相同文字快闪通常是一组；新稿写一次时可复用于该组。新稿明确列出多个动作时分别对应，不能误合并。
- **全文必须使用**：合理分行、合并短句、利用重复镜头，不漏句、不加口号、不补数据。仍放不下时才说明时长与全文之间的冲突。
- **固定时长且允许“能放多少放多少”**：按原顺序选择能完整表达的连续前段，保留数字、单位及限定条件；后续内容列为未使用，不硬塞、不跳着挑高光、不为放完而延长成片。不要再次询问是否允许截稿。
- 先匹配原槽位的节拍和阅读时长，再适配文案。不能把任意一句机械分配为一秒，也不能把长段内容压成极小字号或一闪而过。
- 巨字转场残片是动画的一部分。能归属文字组时同步换成新字；不得把“无法辨识”“转场局部”等分析备注写进画面。

用户提供中英文时逐字采用，仅调整换行。“英文统一XXX”应用到所有英文槽位，明确取消者除外。只给中文而原片有英文时自动配简短对应英文并记录，不保留过时旧英文、不杜撰品牌官方英文名。原片无英文时不添加；“无英文／不要英文／—”表示不显示，空白字段不自动视为删除。

## 3. 制作与合成

### 精确换字

区分背景、几何/粒子、中文、英文与转场，尽可能保留非文字源像素。禁用大块不透明色块盖字。逐帧清除主字、旧英文、叠影、模糊拖尾及进出场残留；用邻近无字帧、对齐的时间中值或局部修复恢复背景。先检查无字底片，再叠新字。同色线框、圆环、光条与文字粘连时建立装饰保护遮罩，不能强开运算抹断细线。

### 镜头重建

依 `references/motion-remake.md` 将参考运动映射到新场景。保留各镜头的构图层级、推拉/旋转/穿行轨迹、主体运动、遮挡、材质、闪帧和衔接；按脚本改变信息载体、场景内容及相关道具。先完成无字场景及动作，再合成确定性的中英文。每项效果关联实际实现和检查帧，缺素材或未实现的效果不能标记为完成。

不要用一条文生视频提示词代替整片精确制作，也不要把静态新图加缩放当成完成复杂场景动画。生成式视频只承担合适的场景片段，精确文字、节拍与最终转场由可控合成完成。生成素材的动作不匹配时继续修正或重建，不仅凭风格相似验收。

### 两种模式共有的文字规则

按实测节拍和轨迹重建逐字入场、叠影、缩放脉冲、旋转、两行滚动和巨字冲屏。依新字数重算同一时段内的错峰；影层与主层绑定同一新稿；英文与装饰分别控制，原本水平的英文不得跟主标题误转。稳定阅读段不裁字，转场有意冲屏的范围按参考执行。

生成标准`plan.json`。镜头重建的无字场景由实际合成制作并预渲染后作为底片，保留对应源工程/渲染证据；包内文字渲染器不会自行生成三维场景。同一份文案与关键帧驱动外部合成及可选AE脚本。镜头重建或混合制作在计划中设置 `motion_manifest` 指向镜头清单，`check-plan`、`render`、`verify`会执行对应严格检查；旧精确换字计划可以省略该字段。结构检查不能代替看画面。

```bash
python3 "$SKILL_DIR/scripts/video_pipeline.py" check-plan --plan "$JOB/plan.json"
# 镜头重建或混合制作还须通过清单检查
python3 "$SKILL_DIR/scripts/motion_contract.py" check --manifest "$JOB/shot_manifest.json" --plan "$JOB/plan.json" --report "$JOB/shot_validation.json"
python3 "$SKILL_DIR/scripts/video_pipeline.py" render --plan "$JOB/plan.json" --output "$JOB/final.mp4"
```

AE路径使用原生文字层、中心锚点、匹配名及ES3兼容JSX；完成真实预览和渲染后才能称AE成片。仅生成JSX不能声称已运行AE。

## 4. 逐镜验收后交付

至少完整播放检查一次，并对照参考检查所有稳定段和每个切点前后至少3帧。问题修复后复查相关镜头；不将明显半成品交给用户挑错，不无故重复渲染。

- **内容**：核对所选文案、中英文、数字、单位、重复层和转场层；允许截稿时核对选用范围及未用内容，而非误判必须塞入全文。
- **动效覆盖**：逐镜独立核对文字、镜头、场景、装饰、转场五项，以及起止帧、运动方向、快慢节拍、遮挡和层级。某项未实现时先修复，不能用其他项的完成抵消。
- **新场景语义**：重建镜头应表达对应脚本，不残留旧主题画面；新场景仍遵循参考动作与风格。只有换字完成时不得报告已完成全部画面重建。
- **画面**：无旧字双影、修复补丁、英文残留、断线或生成素材漂移；稳定段文字可读，实际解码全片无坏帧。
- **技术**：核对所选参考范围、输出尺寸、帧率、帧数、时长、方向和音轨；帧率规范化或长度取整须记录实际变化。

```bash
python3 "$SKILL_DIR/scripts/video_pipeline.py" verify --video "$JOB/final.mp4" --plan "$JOB/plan.json" --report "$JOB/validation.json"
```

主交付为可播放/下载的MP4，按平台要求持久保存。需要编辑时附可用工程；未要求时不额外制作在线表格。简述规格、字体、声音、已用文案范围；如确有差异，具体说明镜头和未达到的效果。不能把代码、提示词、JSX或静态图称为视频，也不能把非原生AE输出称为原作者工程直接换字或逐像素完全相同。
